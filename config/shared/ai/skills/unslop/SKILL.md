# Unslop

Use when asked to tighten prose. Edit only the named text; do not silently rewrite code comments, policy, or unrelated files.

- Cut stock openings, flattery, generic conclusions, needless repetition, and claims without a source.
- Replace abstract claims with the specific mechanism, observable result, or next action. If a sentence could describe any project, make it specific or remove it.
- Prefer plain words and readable sentences over jargon, forced brevity, or a rigid punctuation rule. Keep distinctions, caveats, citations, and safety steps that affect meaning.
- Return the revised passage or a scoped diff. If an important claim cannot be supported, flag it rather than inventing support.
